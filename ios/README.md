## 二、4.9 这一版做了什么

### 上下大黑边：真正的病因
`TabView` 和播放页都是**按安全区布局**的。里面的背景用 `ignoresSafeArea()` 能画到状态栏 /
底部横条上，但这条链路上只要挂了 `.clipShape(RoundedRectangle(cornerRadius: …))`，
**裁剪边就是安全区矩形 —— 圆角为 0 也照样硬切一刀**，铺出去的部分被削平，露出底下的深色层。
4.6 加卡片堆叠时给根 TabView 套了裁剪，黑边就是从那一版开始的；4.8 只调了播放页的修饰符顺序，
裁剪还在，所以「依旧」。

改法：`Theme.swift` 新增 `CardClip`，**圆角为 0 时什么都不做**。

| 位置 | 以前 | 现在 |
|---|---|---|
| 根 TabView | 无条件裁 | `CardClip(active: isOpen, radius: 34 - 20 * pull)` |
| 播放页 | 无条件裁 | `CardClip(active: dragOffset > 0.5, radius: min(34, dragOffset / 5))` |

底层配色也一起改了：常态铺 `AppBackground`（页面同色），播放页打开时才换成 `#212121`，
以后任何没铺到的安全区露出来都是同色，不可能再出现黑条。

## 二·旧：4.8 这一版做了什么

### 1. 专辑详情：专辑名 / 歌手名颠倒
Apple Music 里**专辑名是大字**，艺人是下面小字。之前 `displayArtist` 被放在 21pt 粗体、
专辑名放在 13pt 灰字，正好反了。现在是：专辑名 21pt 粗 → 「艺人 · 年份」13pt 灰 → 曲目数。

### 2. 点播放时的「色块闪烁」
| 来源 | 以前 | 现在 |
|---|---|---|
| 封面占位 | 资料库曲目解码前显示按歌名哈希取色的**彩色方块**，播放页那块有 300pt 大，翻歌时整块变色 | 一律中性灰（20% 白）+ 淡入；只有本地无内嵌封面才用彩色 |
| 主题切换 | 播放页写死 `.preferredColorScheme(.dark)`，在页面还滑入、菜单露在外面的 0.4 秒里整个窗口翻深色 | 改成「完全盖住之后才切、开始下滑之前就切回来」，两次切换都发生在被遮住时 |

### 3. 重大 Bug：播放页上下大黑边
播放页自己 `.clipShape` 裁圆角，而它当时只在**安全区**内布局 —— 裁切边界就卡在状态栏下沿
和底部横条上沿，上下各留一条纯黑。现在：

```swift
GeometryReader { … }
    .ignoresSafeArea()          // 铺满整屏
    .background { … }
    .clipShape(RoundedRectangle(cornerRadius: …))   // 圆角裁到屏幕边缘
```

内容再用 `SafeArea.insets` 往里让（`padding(.top, safe.top)` / `padding(.bottom, safe.bottom)`）。
顺手让**封面和标题区也能往下划收回**（以前只有抓手和顶栏能划）。

### 4. 专辑排序：本艺人的正式录音室专辑优先
`albums(from:matching:)` 打分排序（分小越靠前）：

| 条件 | 分值 |
|---|---|
| 专辑艺人里包含搜索词（本人的专辑） | −1000 |
| 合辑 / Various Artists | +400 |
| 曲目 ≥ 5 / ≥ 10 | −60 / −40 |
| 单曲、EP（≤ 2 首） | +40 |
| 年份较新 | 最多 −30 |

分数相同则保持搜索结果的相关度顺序。

### 5. 播放页比例放大

- 封面 **屏宽 82%**、上限 340（原 76% / 322）
- 竖向节奏 24 / 20 / 18 / 18，省下的高度全给封面
- 歌名 22→24、艺人 17→18、时间 11→12
- 控制排：播放键 42→48、上一首/下一首 27→30、列表与循环 19→21、音量图标 10→12

### 6. 训练卡：字号跟上器皿
动作名 17→20、状态 11→12、副行 11→12、休息环 56→62、按钮 54×29→64×31（字 11→13）。

## 二·旧：4.7 这一版做了什么

- 专辑页顶部「播放 / 随机播放」两个胶囊按钮，曲目按碟号 + 音轨号排
- 网格下面是「歌曲」列表，命中的歌仍可一键直放

### 播放页：对齐与节奏
```
            ── 抓手 ──
  ⌄        正在播放        ⋯
      ┌───────────────┐
      │     封面       │   ← 屏宽 × 0.76，上限 322
      └───────────────┘
  歌名 22 粗 ┐
  艺人 17 灰 ┘ ← 与封面左边缘对齐
  ═══ 进度 ═══  ← 与封面等宽
  0:12      -3:20
   ☰  ⏮  ▶  ⏭  🔁
  🔈 ═══ 音量 ═══ 🔊
```

- 歌名、进度条、控制排、音量条统一对齐到**封面的左右边线**：`pad = max(24, (屏宽 - 封面)/2)`，
  不再是各写各的 24 / 24 / 20 / 22。
- 竖向间距固定成一套：封面→标题 26、标题→进度 20、进度→控制 22、控制→音量 16。

### 下拉退回：真的有「回到上一级」的动效
- 播放页不是独立窗口层了，是根视图里的一张卡片。拖动时把进度写进 `PlayerPresenter.pull`，
  底下 TabView **实时**放大（0.94 → 1）、变亮（遮罩 0.42 → 0）、圆角收小（34 → 14）。
- 播放页自身圆角随拖动 0 → 34 长出来，不再出现大片黑边。
- 松手超过 110pt（或预测滑动 > 260）才真的关闭，否则弹回原位。

### 训练
- 点训练卡打开**训练面板**（sheet，默认 large，可下拉到 medium）：重量 / 次数步进、
  完成一组、本次记录可删、结束训练，和训练页同一个 `Store` / `RestTimer`。
- 训练卡更高：竖向内边距 12 → 15、休息环 50 → 56、动作名 16 → 17、按钮 52×26 → 54×29。
- 右侧竖排：`+30`（或休息秒数）→ **完成** → 跳过。完成 = 记一组 + 自动开始休息。

### 播放列表：直接拖
- 不用先点「排序」了：进来就是排序态，右侧把手常驻，**任意一行上下拖动**即可改顺序，
  松手即时生效（按新顺序重建系统队列并续上原播放位置），点一下仍然是跳到那首。

## 二·旧：4.5 这一版做了什么

### 1. 专辑封面：所有位置都是真封面

之前只有全屏播放页有封面，迷你播放条、正在播放卡片、播放列表全是灰色占位图。
原因是那几个位置只认网络图地址（`artworkURL`），而资料库曲目根本没有这个地址。

现在统一走 `ArtworkStore`：按 `persistentID` 从 `MPMediaItem` 取真实封面，内存缓存 + 后台解码，
列表出现时预取前 12 张。所有位置（列表行、迷你条、正在播放卡、播放列表、全屏页）共用这一份。

### 2. 点播放不再卡一大下

两个根源都拔掉了：

| 卡顿来源 | 原因 | 现在 |
|---|---|---|
| 设系统队列 | `setQueue` / `nowPlayingItem` / `play` 都是跨进程调用，一次几百毫秒，以前整套在主线程同步跑 | 界面状态先就位（点下去立刻有反应），系统队列丢后台串行队列；队列没变就不重建 |
| 0.1 秒轮询 | 每 0.1 秒读 4 个 XPC 属性 = 每秒 40 次跨进程调用，全压主线程 | 0.1 秒只在本地外推时间，0.5 秒才跟系统对一次账，偏差 < 0.35 秒不纠 |

另外封面以前是主线程同步解码 600×600 的图，现在也在后台，取到后自动刷新。

### 3. 搜索：打分 + 拼音

| 机制 | 说明 |
|---|---|
| 多词 AND | 输入「周杰伦 稻香」必须两个词都命中，不再「沾一个词就算」 |
| 分档打分 | 歌名完全等于 100 · 歌名里某词等于 92 · 歌名前缀 88 · 歌名包含 74 · 艺人 64 起 · 专辑只有 32 |
| 相关性下限 | 有强命中时，纯靠专辑名擦边命中的结果直接丢掉（就是之前那堆「无关的歌」） |
| 拼音 | `qt` → 晴天，`qingtian` → 晴天，`zhoujielun` → 周杰伦；索引在后台建时算好，不拖慢输入 |

搜索范围仍然只有你自己的资料库，搜到的每一首都能整首播放（会员身份直接生效）。
为什么不用 MusicKit：整首播放曲库任意歌曲需要 `com.apple.developer.musickit` entitlement，
只有付费开发者账号能勾选，Sideloadly 自签一定没有。MediaPlayer 这条路只需要
`NSAppleMusicUsageDescription`，自签也能用。

### 3.5 搜索结果按专辑排版

搜出来不再是一串散歌，而是一张专辑一块：

```
[封面] 叶惠美                    ▶
       周杰伦 · 2 首
──────────────────────────
   1   以父之名                 5:42
   2   晴天                     4:29

[封面] 七里香                    ▶
       周杰伦 · 1 首
──────────────────────────
   1   七里香                   4:59
```

- 组内按 **碟号 + 音轨号** 排序，每行左边显示音轨号
- 组标题右边一个「播放全部」，从该专辑第一首开始
- 没有专辑名的散装单曲统一归到「未知专辑」，不会一首一个标题栏
- 顶部统计：`我的资料库 · N 首 · M 张专辑 · 全部可完整播放`
- 队列仍是整串结果，点组内某一首就从那儿接着放（persistentID 精确寻址）

### 4. 进度条 / 音量条：8pt 白灰玻璃

- 从 4pt 加粗到 **8pt**，命中区 26pt
- 轨道是浅灰半透明玻璃槽，已播放段白色（深色模式）/ 近黑（浅色模式），
  0.5pt 高光描边 + 轻微外发光
- 没有圆点把手，按住任意位置拖动，点哪儿跳哪儿
- 音量条拖的仍是真实系统音量（`MPVolumeView` 内部 `UISlider`），和侧边键同步

### 5. 播放页：照 Apple Music 排 · 灰色液态玻璃

背景是**灰色液态玻璃**：`灰底(0.13) + ultraThinMaterial + 两团中性柔光 + 薄白釉面`，只有灰度没有色相。
整页固定深色（`environment(.dark)` + `preferredColorScheme(.dark)`），浅色系统下也一样，状态栏图标自动转白。
因此**进度条 / 音量条是白色**：97% 白填充、0.5pt 高光描边、轻微白色外发光，轨道 22% 白。
封面按 Apple Music 比例：`屏宽 × 0.76`、上限 320、最小 130。

```
        ── 抓手 ──
⌄        正在播放        ⋯
     [    封面    ]        圆角 8，重投影
歌名（20 粗，左对齐）
艺人（20 灰，左对齐）
═════ 进度条 8pt ═════
0:12              -3:20
☰   ⏮   ▶   ⏭   🔁
🔈 ═══ 音量 ═══ 🔊
[ Apple Music 那排歌词/待播/AirPlay → 训练状态 ]
```

底部训练状态：当前动作、第几组、上一组「重量 × 次数」、休息倒计时环 + `+30` / `跳过`，
数据源就是训练页那个 `RestTimer`，两边永远一致。

### 6. 视觉：全局去掉渐变

页面底色改成纯色 `systemGroupedBackground`（原来有三团蓝绿紫柔光）；玻璃卡片的填充和描边都改成单色；折线图区域填充改成 12% 半透明纯色；没有封面时的占位图也从渐变改成纯色。整页不再发灰发紫。

### 7. 底部栏系统原生

`TabView` + `.tabItem`，底层就是 `UITabBar`。编译用 **iOS 26.5 SDK**，所以在手机上自动套用系统的液态玻璃外观，是系统画的，不是仿的。

### 8. 身体数据可按日期补记

「我的」→「记录身体数据」：系统 `DatePicker` 选任意过去日期，填体重/体脂，保存即落点。最近 6 条可长按修改、设为曲线第 1 天、删除。

曲线横轴是**健身第几天**（从 `startDate` 起算），体重/体脂/去脂体重/FFMI 共用一张图，各自量程，左轴第一条、右轴第二条。

## 三、开发要点

- **最低系统 iOS 16.0**（用到 `NavigationStack`、`scrollDismissesKeyboard`）
- 数据落在 `Documents/reps.json`，导出/导入走 `我的 → 数据`
- 休息计时用绝对时间戳，回到前台自动校准；锁屏提醒走本地通知
- 两种播放引擎共用一套对外接口：`.av`（本地/试听，`AVPlayer`）与 `.appleMusic`（完整版，`MPMusicPlayerController`），切换时互相 `stop()`，不会两个声音叠在一起
- 完整版播放时**不写** `MPNowPlayingInfoCenter`——锁屏信息交给系统投送，避免我们覆盖成错误元数据
- 界面样式集中在 `Theme.swift`：`.ultraThinMaterial` + 对角染色 + 1pt 镜面描边 + 柔和外阴影 + 三团模糊色斑背景

## 四、踩过的坑

| 现象 | 原因 | 处理 |
|---|---|---|
| 打不开工程 | XcodeGen 默认生成 Xcode 16 工程格式 | `projectFormat: xcode15_0` |
| 编译机没有新版 SDK | 默认跑在 macos-14 / Xcode 15.4 | 换 `macos-latest` + 脚本选最高版本 Xcode |
| 选 Xcode 脚本报错 |  runner 上有不带版本号的 `Xcode.app`，正则取不到 | 改成纯 shell 比较版本号 |
| `remove(atOffsets:)` 找不到 | 它来自 SwiftUI 对集合的扩展 | `MusicHub` 补 `import SwiftUI` |
| 搜索后跳走就没了 | 3.0 用 MusicKit 搜，没 entitlement 必然失败 | 换 iTunes 公开接口 |
| 只能听 30 秒 | MusicKit entitlement 自签拿不到 | 改走 `MPMusicPlayerController` + 资料库匹配 |
| 键盘收不起来 | 数字键盘没有回车键 | 滑动收 + 键盘「完成」+ 导航栏「收起」 |
| `playbackDuration` 拆包报错 | 它是非可选 `TimeInterval`，不是 `TimeInterval?` | 直接比较，不写 `if let` |
| 浅色系统下播放页背景发白、白条看不见 | `.background{}` 里的材质读的是**外层**环境，外层还是 light | 在背景层内部再套一次 `.environment(\.colorScheme, .dark)` |
| 播放列表编辑态里点行不跳播 | 编辑态的行会把 `Button` 的点击吃掉 | 行内容改 `.onTapGesture`，`@ViewBuilder` 换成显式 `return` |
| 下拉退回露出大片黑边 | 用的是 `fullScreenCover`，那一层下面是空的 | 改成根视图里的卡片 + `pull` 进度联动下层缩放 |
| 播放页上下各一条纯黑 | 只在安全区内布局，`.clipShape` 的裁切边界就卡在安全区边缘 | `ignoresSafeArea()` 铺满 + `SafeArea.insets` 让内容 |
| 点播放整块闪一下颜色 | `.preferredColorScheme(.dark)` 在页面还在滑入、菜单露着时就翻了整个窗口 | 盖满之后再切、下滑之前切回 |
| 翻歌时封面一闪彩色 | 占位块按歌名哈希取色，播放页那块有 300pt 大 | 资料库曲目改中性灰占位 + 淡入 |
| 专辑名和歌手名颠倒 | 把 `displayArtist` 当大标题、专辑名当小字 | 大字给专辑名，小字给「艺人 · 年份」 |

## 六、已知限制（说清楚，不糊弄）

1. **整首播放依赖资料库**。歌不在 Apple Music 资料库（没点过 `+`）就在这里搜不到也放不了。这是 sideload 签名缺 MusicKit entitlement 的硬限制——不是没做，是拿不到授权。
2. **系统音量只有 16 级**。音量条画的是连续值、跟手指走，但实际响度是 16 级跳的（iOS 不开放连续设音量，只能借 `MPVolumeView` 内部的 `UISlider`）。
3. **未在真机验证**。CI 只证明「编译通过 + 包结构正确」，封面加载速度、点播放的响应、拼音搜索命中率都要你装上后实测。
4. 网易云没有开放第三方播放接口，只能 `orpheus://` 唤起官方 App。
